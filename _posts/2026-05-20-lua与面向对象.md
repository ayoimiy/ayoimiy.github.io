Lua的面向对象可以依靠表和元表方法进行实现，从而获取面向对象的某些优势。

#### 类的建立
元表方法被称为方法，也许和它们大部分的值是函数类型有关，然而，我们用到的一下两类原表方法：
- `__index`
- `__newindex`
也可以赋值为一张表，如
```lua
local A = {}
A.__index = A
```
再让A作为另一张表的元表
```lua
local B = setmetatable({},A)
```
那么，此时，访问 `B`中不存在的键就会考虑从A中查找，即
`B.key -->  A.key`

此时可以将`B`看成`A`类的一个对象。
之后，我们便可以给`类A`添加更加多的东西
##### 构造函数
我认为构造函数有两种方式实现。

第一种方式：
```lua
function A:new()
	local obj = setmetatable({},A)
	...
	return obj
end
```

即使用`:new()`函数显式地赋予它构造函数的性质。

第二种方式：
```lua
setmetatable(A,{
	__call = function (self,...)
		local obj = setmetatable({},self)	
		...
		return obj 
	end	
})
```

此时是调用是 `local obj = A(...)`
如 `c++`、`java`、`c#`等几种我接触过的语言，基本上也是以类名来调用函数的，因此我觉得第二种方式更为熟悉。
缺点也很明显，需要多定义一张元表，因此无继承的简单情景比较适合第一种

#### 继承
继承与构造类不同，如果简单地将父类直接设置为子类的元表会出现一个问题，那就是子类和父类对象共用一套元表方法。

举个例子，以元表方法 `__call`为例，假若子类要以这个为构造函数，那么父类的对象也能使用，即`local a = obj(...)`。

再如`__newindex`，如果子类保留某些静态属性的话，当访问的键错误时，其错误可能沿着父类的`__newindex`往上传递

因此我认为继承的时候，子类的元表不能直接指向父类，而是新构建一张表，通过`__index`元表方法访问父类的方法，即
```lua
local classA = {}

local classB = setmetatable({},{
	__index = classA,	
})
```
这样可以方便地修改对类的元表方法而不影响父类实例。

做完上述工作之后，我们发现在其他语言的构造函数中，返回对象这个行为是隐式的，构造函数只对对象本身的字段做初始化。
我们可以将这个逻辑抽取出来单独作为一个函数（顺便简化继承）：
```lua
local function class(Base)
	local classB = setmetatable({},{
		__index = Base or nil 
		__call = function (...)
			local obj = setmetatable({},classB)
			obj:init()
			return obj
		end
	})
	classB.__index = classB
	return classB
end
```
这样我们只需要在`init()`中设置字段初始化即可，而不用再加上返回对象。
