下面几种算法都是从起点不断向外探索邻居节点，直到与终点相连。它们共同维护几个信息集合：

- `open_set`：待处理节点
- `closed_set`：标记已遍历节点
- `path_set`：记录路径

如果节点能唯一映射成一个 `key`，那么用字典就可以大大提高查找和比较的速度，为此需要引入：

- `get_node_key()`：获取节点的 `key`
- `nodes_set`：节点和 key 的字典，用于获取节点

除此之外还需要实现：

- `get_neighbors()`：获取节点周围的邻居

大致流程可以看作：

```text
获取邻居 --> 加入 open_set --> 按某种规则处理节点 --> 移入 closed_set --> 循环至无节点可处理
```

下面几种算法的区别只在于"处理规则"。

## BFS 算法

BFS 全称广度优先算法，即优先处理比较近的节点。

注意，BFS 默认图是**等权的**，即节点距离均匀。因为这个前提，只需建立一个普通队列（FIFO）作为 `open_set`，无需额外计算代价。

Lua 中表的特性使其很容易实现：插入表头、读取表尾，就形成了一个简单队列。

## A* 算法

A* 是启发式的。与 BFS 不同的是，A* 在搜索过程中知道终点的信息，因此引入了**代价**：

- 实际代价：`g(n)`
- 预估代价：`h(n)`
- 总代价：`f(n) = g(n) + h(n)`

### 一致性

对于启发函数 `h(n)`，若对任意两个可达节点 `n_k`、`n_l` 存在三角不等式：

```text
h(n_k) <= c(n_k, n_l) + h(n_l)
```

即：

```text
h(n_k) - h(n_l) <= c(n_k, n_l)
```

这个性质可以保证：对于每条路径 `n = n_0 → n_1 → ... → n_k`，其总代价单调不减。

容易证明：

```text
f(n_k) = g(n_k) + h(n_k)
       = g(n_0) + c(n_0, n_k) + h(n_k)
      >= g(n_0) + h(n_0)
       = f(n_0)
```

由于 A* 按 `f(n)` 升序处理节点，这个性质保证了：每次新增邻居节点时，加入 `open_set` 的节点 `f` 值必然不低于当前节点，因此不会出现"扩展邻居时发现 `closed_set` 中已有节点的 `f` 值更低、需要重新处理"的情况。

### 常用启发函数

以下是几种常见且满足一致性的例子：

- **0 距离**：`h(n) ≡ 0`，此时算法退化为 **Dijkstra**
- **真实代价**：`h(n) = cost(n, goal)`，最理想的一种启发式

在几何空间中：

- **欧几里得距离**：平面或三维空间中允许沿直线移动时使用
- **曼哈顿距离**：`h(n) = |n_x - goal_x| + |n_y - goal_y|`，只允许上下左右移动时使用
- **切比雪夫距离**：八方向移动且对角线代价与直线一致时，`h(n) = max(|dx|, |dy|)`

八向网格中，若对角线代价与直线不同，更精确的形式是：

```text
h(n) = max(dx, dy) + (sqrt(2) - 1) * min(dx, dy)
```

这在该网格中等于真实代价，满足一致性。
