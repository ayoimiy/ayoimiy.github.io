> 这篇笔记暂时不提供“万能配方”。  
> 在版本、容器、材料顺序和残留条件没有写清楚之前，配方表很容易变成一串无法复现的字符串。

## 为什么先做记录模板

炼金结果不只取决于“放了哪两种材料”。同样两种材料，在不同条件下可能出现不同现象：

- 当前游戏版本不同；
- 容器的初始内容不同；
- 材料加入顺序不同；
- 环境温度、火焰或其它材料参与了反应；
- 上一次实验的残留没有清理干净；
- 测试使用了 Mod、种子或特殊游戏模式。

如果记录里没有这些条件，看到结果的人无法判断：这是机制，还是一次污染实验。

## 最小字段集

| 字段 | 为什么需要 |
| --- | --- |
| 日期与游戏版本 | 版本更新可能改变材料与反应 |
| 平台与 Mod 列表 | 排除 Mod 对材料或反应的修改 |
| 种子 | 某些实验需要固定世界条件 |
| 容器类型 | 不同容器的容量、材质或初始状态不同 |
| 材料与用量 | 只写名称不够，比例可能重要 |
| 加入顺序 | 反应可能发生在加入的瞬间 |
| 环境条件 | 火焰、温度、周围液体、封闭空间 |
| 结果 | 产物、颜色、爆炸、气体、无反应等 |
| 复现次数 | 一次成功不等于稳定 |
| 异常与备注 | 卡顿、残留、读档后的变化 |

## 记录格式

先用简单、可读的 YAML 保存原始记录，之后再决定是否转成表格或数据库：

```yaml
date: 2026-10-21
game_version: "待填写"
platform: "Windows / Steam"
mods: []
seed: "待填写"

container:
  type: "待填写"
  initial_contents: "空 / 清水 / 上次残留"

ingredients:
  - name: "材料 A"
    amount: "待填写"
    order: 1
  - name: "材料 B"
    amount: "待填写"
    order: 2

environment: "常温 / 火焰旁 / 封闭空间"
result: "待填写"
reproductions: 0
notes: ""
```

YAML 比表格更适合保存“顺序”和“嵌套条件”。真正发布时，可以再用脚本生成对比表。

## 实验流程

1. **清理容器**：确认没有上次实验的残留物。
2. **固定条件**：版本、种子、Mod、位置和环境尽量保持一致。
3. **只改变一个变量**：第一次只改变材料顺序，不要同时换容器和比例。
4. **记录加入瞬间**：反应可能在材料接触时立即发生，不要只记录最终状态。
5. **重复三次**：三次结果不一致时，先查污染和条件，不要挑最符合预期的结果。
6. **保存原始截图或录像**：颜色、气体和爆炸范围很难只靠文字还原。

## 容易犯的错误

- **把“没有反应”当成失败**：无反应也是有效记录，尤其是排除某个组合时。
- **忽略容器残留**：上一次的酸液、火或药水可能还留在里面。
- **只记录产物，不记录过程**：反应速度、颜色变化和爆炸顺序可能比最终产物更有信息量。
- **把 Mod 环境当成原版**：启用了材料修改 Mod 后，结果不能直接当作原版机制。
- **过早合并条目**：两个看起来相似的结果，可能在条件上完全不同。

## 接下来要补的内容

- 一份材料名称与游戏内译名的对照表；
- 容器与残留状态的标准化描述；
- 从实验记录生成对比表的脚本；
- 版本更新后的复测标记。

在这些基础字段稳定之前，[法术索引](/reference/spells/) 和炼金数据表都不会急着上线大量“结论”。先把可复现性做好。
