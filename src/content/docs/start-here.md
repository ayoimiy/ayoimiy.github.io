这是一个围绕 **Noita Mod 制作** 与 **个人机制研究** 建立的档案库。

它不是一份“唯一正确答案”的百科，也不是把 Wiki 重新抄一遍。这里更关心三件事：

1. 一个 Mod 为什么能跑起来，失败时应该从哪里查。
2. 一个机制现象如何被拆成变量，并留下可复现的实验记录。
3. 哪些结论只是当前版本的观察，下一次更新后需要重新验证。

> 本站是非官方粉丝项目，与 Nolla Games 没有隶属关系。涉及剧透的研究内容会尽量标注，但无法完全避免。

## 从这里开始

### 想做一个 Mod

从 [开发环境与项目骨架](/modding/getting-started/) 开始：找到 `mods` 目录、建立最小项目、让游戏打印第一句话。

然后读 [Lua 脚本入门](/modding/lua-basics/)，理解 `init.lua` 的钩子、实体操作和兼容性写法。

### 想拆解游戏机制

先看 [魔杖机制研究](/research/wand-mechanics/)。它目前是一份研究框架：如何区分施法延迟、充能时间和法力瓶颈，以及怎样记录实验条件。

[炼金实验记录](/research/alchemy-notes/) 则是一份记录模板，刻意不给出未经复现的“配方答案”。

### 想查资料

[法术索引](/reference/spells/) 还在建设中。第一阶段先把数据结构定下来，之后再考虑从游戏数据生成页面和查询工具。

## 阅读约定

- **游戏版本**：Noita 的机制与 Mod API 会变化。文章顶部的版本信息比“发布时间”更重要。
- **代码块**：命令和路径以 Windows / Steam 版为主要示例；Lua 代码默认指 `init.lua` 或 `LuaComponent` 上下文，文章会单独说明。
- **实验记录**：观察到现象不等于解释清楚原因。本站会尽量区分“记录”“推测”和“结论”。
- **来源**：涉及社区文档或他人研究时会尽量给出链接。若你发现遗漏，欢迎在仓库建立后指出。

## 这个 Demo 的边界

当前版本主要验证信息架构、排版和视觉方向。示例文章会保留，但其中的占位内容、版本号与实验数据需要在正式发布前补齐。

技术栈是 Astro + Starlight，内容以 Markdown/MDX 保存在 Git 仓库中，之后通过 GitHub Pages 发布。发布流程、许可证和贡献方式会在外观定稿后单独讨论。
